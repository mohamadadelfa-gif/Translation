## ساختار کار

```text
Book
└── Chapter
    └── Translation Unit
        └── Practice Chunk
            └── Sentence
```

نمونه:

```text
C00
└── C00-S02                واحد ساختاری
    ├── C00-S02-P01        قطعهٔ تمرین، حدود ۲۵۰–۳۵۰ واژه
    ├── C00-S02-P02
    └── C00-S02-P03
```

`S` به معنای واحد ساختاری پروژه است، نه جلسهٔ ۳۰۰ واژه‌ای. برای کار روزمره، واحد معمول منتور `P` است. در صورت نیاز، یک جملهٔ دشوار نیز می‌تواند به‌تنهایی موضوع یک جلسه باشد.

## جای هر فایل

| پوشه | کاربرد |
| --- | --- |
| `sources/` | نسخهٔ مرجع و تغییرناپذیرِ منابع بارگذاری‌شده؛ فقط برای مطالعه |
| `translation-preparation/` | لایهٔ کاریِ مشتق‌شده: ساختار کتاب، فصل‌ها، واحدها و راهنمای مطالعه |
| `translation-references/` | منابع بازیابی، نمایه‌ها، واژه‌نامهٔ پروژه، مفاهیم آلمانی و زیرساخت‌های مرجع/پیکره |
| `drafts/` | پیش‌نویس‌ها و بازبینی‌ها، سازمان‌یافته بر اساس فصل (`drafts/C00/`, `drafts/C01/`, …) |
| `approved-translations/` | فقط ترجمه‌هایی که عادل صریحاً تأیید کرده است |
| `tools/` | ابزارهای آماده‌سازی و استخراج؛ برای مطالعهٔ روزمره لازم نیست |
| `archive/` | نمونه‌های آزمایشی، گزارش‌ها و مواد قدیمی یا کمکی |

## منبع اصلی و نسخهٔ کاری

`sources/` تصویر ثابتِ مواد بارگذاری‌شده در مخزن است و از این پس هیچ ویرایش کاری، تقسیم‌بندی تازه، یادداشت منتور یا اصلاح ترجمه نباید در آن نوشته شود. `translation-preparation/` تنها لایهٔ کاری برای تقسیم‌بندی، نشانه‌گذاری و آماده‌سازی متن است.

وجود فایل‌های هم‌نام یا یکسان در این دو لایه به معنای همگام‌سازی نیست. نسخهٔ `sources/` snapshot منبع باقی می‌ماند؛ هر تغییر کاری فقط در `translation-preparation/` انجام می‌شود.

## چرخهٔ ادامهٔ کار

ابتدا بافت و ساختار جمله را بررسی می‌کنیم، سپس پیش‌نویس عادل را با دلیل و پیشنهاد اصلاح بازبینی می‌کنیم. برای کارهای جدید، نام‌گذاری پیشنهادی چنین است:

- `drafts/C00/C00-S02-P01-draft-01.md`
- `drafts/C00/C00-S02-P01-reviewed-01.md`
- `drafts/C00/C00-S02-P01-review-notes-01.md`
- پس از تأیید صریح: `approved-translations/C00-S02-P01-approved.md`

`MENTOR_WORKFLOW.md` تنها مرجع نهاییِ روش آموزش، بازبینی و evidence gate است. `AGENTS.md` فقط دستورهای عملیاتی کوتاه را نگه می‌دارد؛ `SOURCE-REGISTER.md` نقش و مسیر منابع را ثبت می‌کند؛ هیچ‌کدام نباید workflow موازی بسازند.
